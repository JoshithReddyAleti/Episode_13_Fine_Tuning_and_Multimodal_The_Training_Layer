# 🧬 Synthetic Data Generation — Model-Generated Training Data

> *In 2026, more fine-tuning data is generated by models than written by humans. Done well, it produces high-quality datasets at 100× the throughput. Done badly, it produces mode-collapsed garbage that makes models worse.*

---

## Why Synthetic Data (`why_synthetic_data.py`)

**Real reasons:**
1. **Cost.** 10,000 high-quality task examples for $50-500. Same volume from humans: $10-100K.
2. **Speed.** Days instead of months.
3. **Coverage.** Systematically generate hard cases, edge cases, adversarial cases.
4. **Privacy.** No customer data touched.
5. **Domain adaptation.** Where public data is scarce.
6. **Preference data at scale.** Generating pairs is cheap.

**When it fails:** task requires human judgment the LLM lacks; teacher model has biases you inherit; filters aren't strong enough; skipping the "compare to real" validation.

**Rule:** synthetic data is a multiplier, not a substitute for human oversight. Human-labeled seed + LLM-generated expansion + human-reviewed final = winning recipe.

---

## Self-Instruct (`self_instruct_method.py`)

**Wang et al. 2022 — the paper that launched the modern synthetic data era.**

Method: start with ~175 human-written seed tasks. Prompt LLM to generate new tasks in same style. For each, generate input+output. Filter for quality. Add to seed pool. Repeat.

Result: bootstrapped 52K diverse instructions from ~175 seeds.

Alpaca, WizardLM, Vicuna, and most subsequent instruction-tuned models were built with variants.

**Modern practice:** use GPT-4-class teacher; recipe otherwise similar. Seed set quality determines the ceiling.

---

## Evol-Instruct (`evol_instruct.py`)

**Xu et al. 2023, WizardLM.** Improves Self-Instruct by *evolving* instructions to be more complex.

**Evolution operations:**
- **In-depth evolving:** add constraints, deepen reasoning, add specifics, complicate input, increase reasoning steps.
- **In-breadth evolving:** create new, related but different instruction.

Each round takes existing and produces harder variants. After N rounds, spectrum from simple to complex.

**Why it works:** fine-tuning benefits enormously from *diverse difficulty*. Training data covering only "easy" produces models that fail on "hard."

## Distillation From Larger Models (`distillation_from_larger_model.py`)

**The dominant modern pattern.** Use a large capable model to generate training data; fine-tune a smaller model to imitate.

**Pipeline:**
1. Curate representative inputs.
2. Run large teacher on all inputs.
3. Store teacher's outputs as training data.
4. Fine-tune student on (input, teacher_output) pairs.

**Examples in the wild:** Zephyr (from Mistral-Instruct), Orca-2/Phi series (from GPT-4), distilled Llama variants. Every enterprise that fine-tunes 7B to match GPT-4-quality on a narrow task.

**What you get:** 70-95% of teacher's quality at 10-20× the throughput, 10-50× lower cost/token.

**Trade-off (distillation loss):** small model can't capture every nuance of the large one. On the tails (hard, rare cases), the gap widens.

## Constitutional AI Data (`constitutional_ai_data.py`)

**Anthropic's approach.** Use principles (a "constitution") to have the model critique and revise its own outputs.

Process: model generates initial → critiques against a principle → produces revised. Training data = (input, revised).

**Advantages:** scales alignment without human labels for every case; principles are auditable; works well for safety/refusal.

## UltraFeedback Pattern (`ultrafeedback_pattern.py`)

**Cui et al. 2023.** High-quality preference data at scale via LLM-as-judge.

Pattern:
1. Take a prompt.
2. Generate N responses from N different models.
3. Strong LLM (GPT-4) scores each on multiple criteria.
4. Highest-scored = "chosen", lowest = "rejected."
5. Aggregate into preference dataset.

**Why:** many pairs from few prompts; diversity of source models produces genuinely different responses. The go-to method in 2026 for preference data.

## Quality Filtering (`quality_filtering.py`)

**The single most important step.** Bad outputs contaminate more than they add.

**Filters (in order):**
1. Format validation.
2. Length limits.
3. Repetition detection (n-gram, phrase).
4. Perplexity filtering (very-low = bland; very-high = incoherent).
5. Language ID.
6. Toxicity filter.
7. Coherence check via LLM-judge.
8. Task-specific validators (code passes tests, math correct, JSON parses).
9. Deduplication.
10. Human spot-check (random 100).

**Attrition rate:** raw synthetic → training-ready is 40-80% loss. Budget accordingly.

---

## Deduplication at Scale (`deduplication_at_scale.py`)

**Exact:** hash. Trivial. Catches near-nothing.

**MinHash / LSH:** shingle text into n-grams, hash shingles, compare via Jaccard. Threshold 0.7-0.9. Tools: `datasketch`, `text-dedup`.

**Semantic:** embed each output; find near-neighbors above cosine threshold (0.85-0.95). Slower but catches paraphrases.

**Recommended:** exact + MinHash for scale, semantic on a subset.

Real-world: synthetic data often has **30-60% near-duplicates** before dedup.

## Contamination Detection (`contamination_detection.py`)

**A synthetic dataset generated by GPT-4 will have seen the evaluation benchmarks GPT-4 saw during pretraining.**

**Detect:**
- Exact substring match against test examples.
- N-gram overlap (fraction of test's n-grams appearing in training).
- Embedding proximity.
- Prompted contamination ("have you seen this?").

**What to do:** reject any training example matching a test example; report contamination scores; keep the golden eval set separate from anything the teacher could have seen.

**Rule:** if you don't check contamination, your reported eval numbers are suspect.

## Synthetic Data Pitfalls (`synthetic_data_pitfalls.py`)

**Real failure modes:**

1. **Mode collapse.** Generator produces narrow distribution. Fix: diverse temperatures, prompt templates, source models.
2. **Style/format overfitting.** Model learns teacher's quirks. Fix: normalize surface features; audit for teacher-isms.
3. **Distillation loss on tail.** Teacher handles rare cases; student doesn't. Fix: oversample hard cases; include real examples for rare situations.
4. **Compounding errors** in multi-step generation. Fix: verify final answers automatically.
5. **Bias inheritance.** Teacher biases → student biases, potentially amplified.
6. **Contamination.** Silent quality killer.
7. **False confidence.** Synthetic always looks clean (fluent). Doesn't mean correct. Fix: verification for factual claims.
8. **Recursive self-training collapse (MAD).** Training on outputs of a model trained on outputs → progressive quality loss. Fix: always mix in fresh human-authored data or strong external teacher.

## The Modern Recipe

```
1. Seed: 200-500 high-quality human-authored examples.
2. Expand: Evol-Instruct-style transformations by strong teacher.
3. Diversify: multiple teacher models, temperatures.
4. Distill: teacher generates outputs for many inputs.
5. Filter: 10-stage pipeline.
6. Deduplicate: MinHash + semantic.
7. Contamination check.
8. Human sample review: 100+ spot-checked.
9. Version and freeze.
10. Fine-tune.
```

A small team can build a 20K-example task-specific dataset in 1-2 weeks with a few hundred dollars of teacher API. Compare to $50K+ and 3 months of vendor labeling.
